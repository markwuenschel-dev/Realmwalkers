01 Executive summary

Since pass 4 (2026-07-08) the owner worked the backlog hard: six candidates verified resolved — the greenlet-class invariant is now pinned (NC1a), the sweeper registry leak evicts on the terminal path (C13), retention is a set-based delete (C11), the staleness N+1 is batched (C12), addopts=-rs landed (C9), and the vacuous-e2e flag is gone (C16). The deterministic surface is healthy: backend pytest ran 766 passed / 1 xfailed against a real local Postgres, pyright (src), ruff, ruff format, and the frontend vitest unit suite (343 tests) all pass, and openapi.json is byte-identical to app.openapi().

Headline — A1: CONTEXT.md documents an unbuilt autonomy/authorization subsystem as live invariants. AGENTS.md designates CONTEXT.md the single source of truth that humans and AI agents read as the domain contract. Its glossary states six autonomy/authorization invariants in present-tense declarative language — Autonomy Control (a singleton with enabled/epoch/updated_at), the Autonomy Epoch (stamped and re-checked at claim and finalization), the Operational Hold, Execution Authorization as an append-only grant event, the Approval Blocker record, and an Authorization Requirement kept orthogonal to authority_level. Six of the seven do not exist in code. Verified directly: grep -i epoch src/dominion returns one unrelated timestamp comment; the identifiers AutonomyControl / OperationalHold / epoch_mismatch / autonomous_policy / manual_command / ExecutionAuthorization / ApprovalBlocker have zero matches in src/dominion. The real mechanism is a single KV boolean autonomy_enabled read live per sweeper tick (sweeper.py:43,117,363); authorization is mutable fields on RepairTask (models.py:970,973) — the exact "mutable field" the doc says it is not. The governing ADRs 0030/0031 self-label planning-only; CONTEXT.md jumped to the decided-but-unimplemented design (commit 25a3fe1/#236 resolved the design blockers B-1..B-4, not the code).

The danger is specific: an agent (or human) reading CONTEXT.md would believe autonomous spend is epoch-gated and hold-protected, and would make changes on that assumption. Worse, one live contradiction sits under it — the sweeper's own comments disagree on whether a human-required repair may ever be auto-approved (sweeper.py:59-60 "must never be auto-approved" vs :167-171 "raising the ceiling to human_required opts into full autonomy"), and RepairAuthorityLevel.HUMAN_REQUIRED remains a ceiling-negatable rung (enums.py:289) despite ADR-0031 D16 deciding to retire it as one. The fix splits cleanly: A1a — relabel the six unbuilt terms in CONTEXT.md as planned — is a near-free, high-leverage docs edit (pri 17) that stops the overstatement immediately; A1b (reconcile the ceiling contradiction) and A1c (actually build the subsystem) queue behind an authorization-policy decision.

Two fresh build/contract nits round out the new work. N1: jszip is an undeclared direct dependency — imported only by docxXml.test.ts, absent from package.json, resolvable in CI solely because frontend/.npmrc sets public-hoist-pattern[]=* (hoisting docx's transitive copy); the current local node_modules lacks the hoist, so tsc and vitest are red on a laptop while CI stays green. N2: the new Inject feature ships a GET /enrich/lanes endpoint that no one calls — the panel hand-mirrors the lane list (EnrichScreen.tsx:46-62) with a "keep aligned" comment, so a 4th lane added at router.py:22 silently won't appear in the UI. The Inject surface is otherwise well-built (genuinely stateless, correct none-means-all, reuses the pipeline specialists, well-tested). The carried contract/security gates — C3 nested-JSONB, C4 enums, C14 migration parity, C7 machine-keys, C10 auth, C8 coverage, C2 approval duplication — are unchanged except C14, which now sports a parity test that guards only the harmless direction.
