01

Executive summary

Realmwalkers is a well-built, unusually self-aware codebase with a clean static surface (ruff + pyright zero-error on src/dominion at HEAD) and 804 green tests. The integrity gaps are not sloppiness — they are latent risks beneath a clean surface that current automation cannot catch. Two themes dominate:

1. Hand-maintained mirrors without a guard. The same fact is encoded in two places and kept in sync by hand — an enum restated as a DTO comment, a Python ordering formula re-typed as SQL, a lane vocabulary restated in an LLM prompt, a "matches CI" claim copied into five docs/scripts. Six candidates share this root cause, and the repo has already been bitten twice by it (the sensory lane going silently dead, combat repairs mis-routing) — each fixed locally, never generalized to the next hop.

2. Verification blind spots on the highest-risk surfaces. There is no test at any layer that drives a real HTTP request into the FastAPI app (routers are tested as plain functions), no coverage measurement anywhere, and the autonomy/settings control plane plus the self-modifying rule-learning path have zero tests. Separately, the hand-rolled migration path has a self-documented forward-drift gap (independently flagged by two lanes) that "boots green on CI but throws UndefinedColumn in production."

Three confirmed, contained bugs were found in logic no linter checks: a character-state ledger delta double-applied on scene re-approval, an off-by-index in chapter-sequence chaining, and a dict(None) crash on legacy settings rows. All three are high-locality with one-line fixes and clear regression tests. One candidate — the unwired ADR-0028 substrate — is a genuine wire-vs-delete decision and is marked needs-human-decision.

Overall repo grade

B-
Justified from the scorecards below, not asserted. Craftsmanship and static hygiene are B/B+ (clean linters, disciplined test fixtures, exemplary self-documentation, real parity tests where they exist). Verification readiness drags to C (no HTTP harness, no coverage floor, control-plane untested) and blast-radius guarding is C+ (many mirrors, guarded only sometimes). The confirmed bugs are contained (high locality, one-line fixes), so they lower severity but not the structural grade. Net: a solid codebase one disciplined loop away from B+, held back by systemic verification gaps and un-generalized mirror guards.

Lane findings & health

Lane 1 — Deepening seams. Module depth is uneven in a learnable way: the repo demonstrably knows how to build a deep module with a stated contract (scene_packet/__init__.py's facade + __all__) and how to guard a prefetch twin (telemetry_diagnostics + its parity test), but did not apply that discipline to sibling subsystems built around the same time. Fed: PKT-PIPE, PROD-FACADE, TWIN-PARITY, TELEM-AGG, REPAIR-GOD, LLM-SIG.

Lane 2 — Graded integrity. Static surface is genuinely clean; the real findings live beneath it in logic no linter checks, clustering around "two derived values computed from what should be the same source but not kept in lockstep." Fed: LEDGER, SEQ-IDX, GLOBALS, ORDER-BACKFILL, CTX-ADR, DEAD-FLAG, BEAT-NOUN.

Lane 3 — Blast radius. Three of seven findings sit next to a comment describing a past incident of the identical shape; two got real parity tests. The fixes have all been local, never generalized — so equivalent landmines keep surfacing one hop away. Fed: VERIFY-GATE, MIG-DRIFT, ENUM-STR, SEV-ALIAS, PLANNER-TAG, PKT-BODY, ARTIFACT-TYPE.

Lane 4 — Verification readiness. The worker-level pyramid is in good shape (60 db-backed + 59 unit files, schema-setup-once, a DB-required hard-fail gate, fake-clock sweeper test, a strict xfail). The gaps are "this seam was never wired into the pattern," and they compound: no HTTP harness → lands on the untested control plane → invisible because no coverage tool. Fed: HTTP-HARNESS, CTRL-PLANE, MIG-DRIFT, ADR28-SUB, COV-FLOOR, IMP-EVID, E2E-GATE, CH1-GOLD.

12

Verification readiness

The testability picture is the report's most consequential axis. Harnesses that must exist before common fixes can be proven:

  • An ASGI client fixture (httpx.AsyncClient(transport=ASGITransport(app=app)), zero new deps — httpx>=0.27 is already a dependency). Without it, no router fix can be verified end-to-end. Blocks proving CTRL-PLANE and any future router bug. → HTTP-HARNESS.
  • A coverage tool + floor (pytest-cov). Its absence is why CTRL-PLANE, IMP-EVID, and DEAD-FLAG were invisible to CI and only found by manual audit. → COV-FLOOR.
  • A migration baseline-snapshot diff — the only way to falsify forward-drift; the current fixture (fresh create_all every run) structurally cannot see it. → MIG-DRIFT.

Fixture health is otherwise good, with one gap: the ch1_bad_run goldens have no regeneration story (CH1-GOLD), where the sibling scene_fidelity corpus already has a manifest-validation pattern worth copying.
