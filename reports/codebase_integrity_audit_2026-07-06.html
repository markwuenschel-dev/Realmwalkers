Data / Schema / ContractBug & CorrectnessWiringconfirmed (line-quoted)
Location: workers/production_repair.py:650 — RepairTask.status.in_(["queued", "running", "repair_queued"]) inside the overlapping-span conflict query in apply_repair_task. Contract: shared/enums.py:267 RepairTaskStatus = {queued, running, waiting_for_human, verified, rejected, failed, cancelled}. "repair_queued" is not a member — it exists only on IssueStatus (enums.py:242).
Friction / failure mode: two independent defects in one predicate. (1) Dead arm: "repair_queued" can never equal a RepairTask.status, so that third literal matches nothing — silent, no error. (2) Gap: the set omits waiting_for_human, so a conflicting span-repair parked for a human is not seen as in-flight, letting a second overlapping repair through the conflict gate on the same scene span.
Root seam / rule violated: a controlled vocabulary (RepairTaskStatus) must have exactly one authoritative definition, and every query that filters on it must reference real members — never a free string borrowed from a sibling enum. This is the same class as the prior C1 sensory-tag bug: a literal that compiles but silently never matches.
Facts vs inference: CONFIRMED the literal and the enum are line-quoted; the dead arm is mechanical. DECISION whether waiting_for_human (and/or running) belongs in the in-flight conflict set is a repair-semantics choice, to be pinned in the candidate gate — the mechanical fix (drop the invalid literal / use enum members) is safe on its own.
Leverage 8Locality 8Enforceability 9Risk 3
Recommended branch: fitness-check — state the rule → add a failing check asserting every status literal used in repair queries is a valid RepairTaskStatus member (a lint-style AST/grep test, or a typed helper) → replace the string list with enum members → decide the waiting_for_human question with a test that pins the intended conflict semantics → green → prove.
Enforceable check: test that the conflict query's status set equals an explicit, enum-typed constant (e.g. _IN_FLIGHT_REPAIR_STATUSES: set[RepairTaskStatus]), plus a guard that no repair query references a string not in RepairTaskStatus. Prevents any future cross-enum literal from slipping into a status filter.
Adjacent / out of scope: broader repair-conflict redesign; other repair queries beyond this predicate unless the guard surfaces them; the combat-lane routing (D2).

New tests/test_repair_conflict_status.py (8 tests): behavioral — waiting_for_human/running overlaps block, terminal + non-overlapping do not; contract guard — in-flight set ⊆ RepairTaskStatus (catches any foreign literal like the old "repair_queued"), and open ∪ terminal partitions the enum so a future status can't silently fall through.
