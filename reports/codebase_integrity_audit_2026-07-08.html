1 · Executive summary

Third audit pass, taken on the branch that just shipped N1 — the greenlet enrich-after-commit class that dominated pass 2. The lanes independently re-verified that fix and the two structural gates that closed alongside it, then found the backlog re-scored and one new open bug of the very same greenlet family — this time in the autonomy sweeper.

N1 — CONFIRMED FULLY CLOSED on the API surface. The class is narrow and now fully covered. SessionFactory sets expire_on_commit=False (shared/db.py:14), so the 500 fires only for the 5 models whose updated_at carries onupdate=func.now() (ScenePacket, ChapterSequence, ProductionRun, RepairTask, DraftRunTimeline). Every mutating endpoint that serializes one of those now has await session.refresh(...) first (13 sites in routers/production.py, 4 in scene_packets.py, 2 in packets.py); the remaining model_validate sites are GET handlers reading freshly-SELECTed rows (safe). The 5 other mutation routers return models with no onupdate column — structurally immune. The landed tests are red-capable and fix-coupled (reverting any refresh re-raises MissingGreenlet).
Headline (new): the same greenlet class is still open in the sweeper. In sweeper.py:224-270, each task is a live ORM object; apply_repair_task(session, task.id) re-gets the same session-identity object and mutates it (task.status=…) inside async with session.begin_nested(). On savepoint rollback those attributes expire, and the except branches then read str(task.id) off the expired object outside the savepoint — a sync lazy-load → MissingGreenlet. This precisely matches the code's own documented-but-unreproduced defect (sweeper.py:367-368: “a data-specific greenlet_spawn fires OUTSIDE the wrapped stages on one real run and no synthetic run reproduces it”). The sibling drain in background_work.py:192-213 already uses the correct pattern — capture the id as a primitive before the try, rollback, then session.get() to re-fetch. The sweeper does not.

Two carried structural gates are now closed and are not re-reported as open:

  • N5 flat-DTO drift — the codegen:check gate (frontend/package.json → ci.yml:178) diffs openapi.json ↔ generated.ts and is CI-enforced. The nested-JSONB hand-mirror portion of N5 remains open (see C3) — that is the surface the flat gate structurally cannot see.
  • N11 DB-skip “fake-green” — CI sets DOMINION_REQUIRE_DB=1 and conftest.py:139-141 turns a missing DB into pytest.fail, not skip. A silently-green no-DB run is impossible in CI. Only a minor local visibility gap remains (no -rs in pyproject addopts).

The rest of the pass is a re-scored backlog plus four new maintainability/reliability findings in the autonomy path (sweeper registry growth, retention bulk-delete idiom, a staleness N+1), a model↔migration coordination fitness-check, and the two standing human-decision forks (N8 API auth, and the two-tier packet policy/enum ADR that gates N4/N6/N7 field-typing). One lane conflict was adjudicated: the Blast-radius lane reported “no import shims” in workers/production.py; the Deepening-seams lane reported 33. Deepening-seams is correct — captain re-ran the grep: exactly 33 function-local imports, and neither production_sequence nor production_repair imports production back, so the guarded cycle does not exist on these edges (C5).

Lane sources
graded_integrity (GI1) · captain-verified
Symptom

Root seam

Action / mode
direct-fix + fitness-check · sequential (localized to sweeper.py).
Fix
Capture tid=str(task.id), authority=task.authority_level as locals before begin_nested(); use those (plus session.get re-fetch if a row is truly needed) in every except/record_activity path, mirroring background_work.py.
Enforceable check
