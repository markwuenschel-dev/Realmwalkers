1 · Executive summary

Fourth pass, taken on main with both greenlet fixes now merged — N1 (routers) and C1 (sweeper). The swarm re-verified C1, re-validated the entire carried backlog against current main with fresh line-level evidence, and swept for new issues. No new live bug was found — but three lanes, from three different angles, independently converged on the same structural truth.

C1 — VERIFIED CLEAN and merged. All three begin_nested() savepoints in _sweep_one_run read only primitives captured before the savepoint; begin_nested exists only in sweeper.py repo-wide, so the new AST guard covers the whole savepoint surface. The guard is sound (its negative fixture proves it red-capable). The two candidate sibling paths — background_work.drain_queued_repair_tasks and worker.py's rollback path — were checked and are already clean (both capture the id as a primitive and re-session.get the parked row).
The headline is now structural, not a bug. N1, C1, and the earlier mark_scene_packets_stale fix (975809d) are four fixes for one class — “read an ORM attribute after commit/savepoint-abort on an async session → MissingGreenlet 500” — each solved per-symptom, differently:
  • DS1 (seams): the enrich boundary (enrich_*_out → model_validate(row)) has an unstated precondition — “attributes must be loaded, not expired” — leaked to ~14 hand-written await session.refresh(...) calls across routers/production.py and scene_packets.py. A new endpoint can forget it and reintroduce a prod 500.
  • GI5 (integrity): the whole class is currently latent only because SessionFactory(..., expire_on_commit=False) (shared/db.py:14) — an unpinned, uncommented, load-bearing invariant. Flip it to SQLAlchemy's default and every post-commit ORM read across routers and workers becomes the greenlet class, fleet-wide.
  • VR3 (verification): the static guard fences _sweep_one_run only; the ≥3 sibling functions that received the same fix have runtime regression tests but no static guard, so the class can re-enter any of them undetected.
These merge into the pass-4 headline NC1 — close the async-serialize greenlet class structurally, with a near-free first step (pin the invariant) and a design tail (a serialize-safe seam so routers stop hand-writing refresh). Recurrence risk is real: 4 fixes in ~4 commits.

Everything else is the carried backlog, re-validated and mostly unchanged. Refreshed evidence sharpened three: C4 (enum triple-mirror) now measured at 92 importer files, 112 free-text status columns with zero DB CHECK, and 69 TS bare-literal sites; C14 (model↔migration parity) is the highest-leverage contract gate — a model-only column add is green on CI's fresh create_all DB but throws UndefinedColumn against the persistent Railway Postgres; C6 expanded — tests/ is excluded from type-checking entirely. C9 was re-scored down (all three sanctioned runners already pass -rs; only a bare ad-hoc pytest loses skip visibility). The two human-decision forks persist: C10 (no API auth, severity bumped to 5) and C2 (two-tier approval-policy ADR). A fake-green hunt across the suite came back clean — one intentional skip, no self-skips.
