1 · Executive summary

Second audit pass after Wave 1 (PR #182) merged 10 candidates. Wave 1 held up cleanly — the lanes independently re-verified the scene_packet facade closed its router leak, types.ts was slimmed to generated re-exports, config paths centralized, and 8 new test assets landed (whole-run harness, sweeper loop/embed seams, e2e smoke, reconcile regressions, fence-strip test). No Wave-1 regressions were found.

The pass is dominated by one discovery and a re-scored backlog:

  • The greenlet MissingGreenlet bug fixed at ship time is a systemic class (N1). The graded-integrity lane enumerated ~12 sibling handlers — mostly in api/routers/production.py — that mutate an onupdate-updated_at model, commit, then serialize via model_validate/enrich without session.refresh(): each a latent 500. Only 3 sites carry the fix. This is the headline candidate and pulls the reliability grade down to 2/5.
  • The four structural verification gates (full pyright in CI, coverage tooling, local DB-skip visibility, enforced LLM mock seam) all re-verify unchanged (C13/C14/C15/C19).
  • The two-tier packet duplication (approval policy C5, enum vocabulary C11) and the types.ts contract surface (drift gate still absent C1; nested-JSON hand-mirrors are the largest unguarded surface) persist.
  • C2 sharpened: production.py's ~33 circular-import shims guard a cycle that doesn't exist on the observed edges — a cheap hoist plus a real god-module design question.
  • C6 (no API auth) and C11 (enum consolidation) remain human-decision-blocked.
Captain adjudication — one lane finding rejected. The verification lane's VR2-6 claimed the Wave-1 greenlet fix is "fake-green" because expire_on_commit=False makes the refresh a no-op. This is refuted on two grounds: (1) the graded-integrity lane's mechanism analysis — server-side onupdate columns are expired at flush regardless of expire_on_commit; and (2) direct observed evidence — the first CI run literally failed on test_mark_stale_reconciles_beats with the greenlet error and passed only once the refresh was added. That test is red-capable in CI. VR2-6 is not carried into the ledger.

N1 Greenlet enrich-after-commit is a systemic class — ~12 unrefreshed sibling handlers direct-fix + fitness-check

lane: graded_integrity (+ linked: C7 sweeper race) · prior: new · category: Bug · execution: connected-impact-sweep
Summary: The Wave-1 mark_scene_packets_stale 500 has ~12 twins. Each mutates a model whose updated_at uses onupdate=func.now() (server-computed), commits, then serializes the row via model_validate/enrich_*_out (which reads the required updated_at) without a preceding session.refresh(). SQLAlchemy expires server-computed columns at flush even under expire_on_commit=False, so the read is a sync lazy-load on the async session → MissingGreenlet 500.
Root cause: No single serialize/refresh seam for the 5 onupdate models (ScenePacket, ChapterSequence, ProductionRun, RepairTask, DraftRunTimeline); each handler hand-rolls mutate→commit→enrich and 3 remembered the refresh, ~12 didn't.
  • shared/db.py:14 expire_on_commit=False; shared/models.py:280,305,637,812,880 — the 5 onupdate updated_at models; schemas.py:1602,1771,1970 Out schemas make updated_at required (forces the read).
  • Fixed (prove the pattern): scene_packets.py:306 (update), :453 (mark-stale, Wave-1), production.py:472 (align_sequence_scene_count) — all carry the refresh + identical comment.
  • At risk (mutate+commit+serialize, no refresh): scene_packets.py:390 batch-approve; production.py:186 cancel, :196 resume, :532 approve-final, :354/:381 apply/approve-apply repair, :409 reject, :421 rollback, :459 update-sequence, :492 approve-sequence, :504 revise-sequence, :447 derive-sequence.
sev 4conf 4lev 5loc 4test 4 blast 4regr 2human 2priority 13
Preferred fix (not whack-a-mole): a single enrichment seam — either the Out-builders refresh the row they return, a refresh_then(session,row) wrapper, or add updated_at to RETURNING/eager_defaults so no reload is needed. Enforceable check: a fitness test/lint asserting "no model_validate/enrich of an onupdate model after commit without a preceding refresh" makes the class non-recurring. Batch-approve (scene_packets.py:390, highest-traffic) first. Likely also kills C7 (see N2).
